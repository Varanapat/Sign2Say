## 1. Sign2Say: แปลภาษามือไทยเป็นข้อความด้วย landmark

**บนสไลด์**
- ชื่อโปรเจกต์, ชื่อทีม
- ภาพ: วิดีโอคนทำท่า → โครงกระดูก landmark → คำ "ฉัน ชอบ เที่ยว"

**พูด**
> Sign2Say คือระบบรู้จำภาษามือไทยจากกล้องธรรมดา โดยไม่ใช้ภาพดิบเป็นหลัก แต่ใช้ตำแหน่งจุดสำคัญของร่างกาย มือ และหน้า หรือ landmark ที่สกัดด้วย MediaPipe แล้วส่งเข้าโมเดล deep learning เพื่อทายคำ และต่อยอดไปถึงการรู้จำทั้งประโยค วันนี้จะเล่าตั้งแต่ข้อมูล สถาปัตยกรรม ผลการทดลอง ไปจนถึงความทนทานและความเร็วของระบบ

## 2. ปัญหาและคำถามวิจัย

**บนสไลด์**
- ปัญหา: ผู้ใช้จริงคือ "คนที่โมเดลไม่เคยเห็น" → ต้องวัดแบบ **signer-independent**
- 3 งาน: ISLR (คำเดี่ยว) · CSLR (ประโยค) · gloss → ไทย
- RQ หลักที่ตอบได้แล้ว: RQ3 (temporal), RQ5 (split), RQ6 (จุดหน้า), RQ7 (CTC vs segment), RQ9 (รวม dataset) + RQ-S ของเพื่อน (spatial / temporal / spatiotemporal)
- โครงการนำเสนอ: ส่วนที่ 1 ระบบหลัก → ส่วนที่ 2 วิเคราะห์สถาปัตยกรรม → ส่วนที่ 3 รวมสองส่วน

**พูด**
> งานวิจัยภาษามือจำนวนมากรายงานความแม่นยำสูง แต่แบ่ง train/test แบบสุ่ม ทำให้คนเดียวกันอยู่ทั้งสองฝั่ง ซึ่งไม่ตรงกับการใช้งานจริงที่ผู้ใช้เป็นคนใหม่เสมอ เราจึงตั้งการวัดหลักเป็น signer-independent คือคนใน test ไม่เคยอยู่ใน train เลย และตั้งคำถามวิจัยพร้อมสมมติฐานไว้ก่อนรันทุกข้อ เพื่อให้ผลที่ออกมาตัดสินได้ว่าสมมติฐานถูกหรือผิด
>
> งานแบ่งเป็นสามส่วน ส่วนแรกคือสร้างระบบหลักและวัดว่าใช้กับคนใหม่ได้ดีแค่ไหน ส่วนที่สองคือการวิเคราะห์เชิงลึกว่าโครงสร้างโมเดลแบบไหนเหมาะกับภาษามือ และส่วนที่สามคือนำข้อค้นพบจากส่วนที่สองกลับมาทดสอบกับระบบหลัก

## 4. Data pipeline

**บนสไลด์** (แผนภาพเป็นลูกศร)
```
วิดีโอ → MediaPipe Holistic 0.10.21 → เลือก 54 จุด (C54) → เติมช่องว่าง ≤ 5 เฟรม
      → normalize (จุดกลางไหล่ = 0, หารด้วยความกว้างไหล่) → resample เป็น 64 เฟรม
      → 7 ช่องต่อจุด: x, y, z, Δx, Δy, Δz, valid
→ tensor [64 เฟรม × 54 จุด × 7]
```
- C54 = แขน 6 (pose 11–16) + คิ้ว/ปาก 6 + มือ 21 × 2
- schema เดียวกับ CSV ของ TSL-51 → ✅ ตรวจแล้วว่าจุดตรงกัน (ระยะ median 1e-4)
- Split: 10 fold แบ่งตามผู้แสดง (train ~23 คน / val 3 / test 3)

**พูด**
> ขั้นแรกเราสกัด landmark ด้วย MediaPipe Holistic แล้วเลือก 54 จุดให้ตรงกับ schema ของ TSL-51 เพื่อให้ใช้สองชุดข้อมูลร่วมกันได้ เราตรวจแล้วว่าจุดของสองชุดตรงกันจริงโดยรัน MediaPipe ซ้ำบนวิดีโอของ TSL-51 แล้วเทียบกับ CSV ต้นฉบับ
>
> จากนั้น normalize ให้ไม่ขึ้นกับตำแหน่งและขนาดตัวคนในภาพ โดยใช้จุดกลางไหล่เป็นจุดศูนย์ และหารด้วยความกว้างไหล่ แล้วปรับทุกคลิปให้ยาว 64 เฟรม ทุกจุดมี 7 ค่า คือพิกัด 3 มิติ ความเร็ว 3 มิติ และค่าบอกว่าจุดนั้นตรวจเจอหรือไม่
>
> การแบ่งข้อมูลเป็น 10 fold ตามผู้แสดง แต่ละ fold มีคนใน test 3 คนที่ไม่อยู่ใน train

## 5. สถาปัตยกรรมหลัก: S2S-LTR

**บนสไลด์** (แผนภาพ)
```
input [64 × 54 × 7]
   ├─ มือซ้าย 21 จุด → MLP → 96
   ├─ มือขวา 21 จุด → MLP → 96      ← part-aware spatial encoder (ต่อเฟรม)
   ├─ แขน 6 จุด     → MLP → 32
   └─ หน้า 6 จุด    → MLP → 32
   concat → 256 + LayerNorm
   [CLS] + learned positional encoding (65 ตำแหน่ง)
   Transformer encoder × 4 (d 256, 4 heads, FFN 1024, pre-norm)
   [CLS] → LayerNorm → Linear → 184 คำ
```
- 3.28M params · ไฟล์ 12.5 MB
- Training: AdamW lr 3e-4, wd 0.05, warm-up 5 + cosine, label smoothing 0.1, batch 32, ≤ 150 epoch (patience 30)
- Online augmentation: หมุน ±10°, scale 0.9–1.1, เลื่อน, noise

**พูด**
> โมเดลหลักชื่อ S2S-LTR แบ่งเป็นสองส่วน ส่วนแรกคือ spatial encoder แบบแยกตามส่วนของร่างกาย มือแต่ละข้างมี MLP ของตัวเองและได้มิติมากที่สุด 96 เพราะข้อมูลภาษามือส่วนใหญ่อยู่ที่รูปมือ ส่วนแขนกับหน้าได้ 32 แล้วนำมาต่อกันเป็นเวกเตอร์ 256 มิติต่อเฟรม
>
> ส่วนที่สองคือ temporal model เป็น Transformer 4 ชั้น โดยเพิ่ม token พิเศษ [CLS] ไว้หน้าลำดับ แล้วใช้ output ของ [CLS] ทายคำ ทั้งโมเดลมีพารามิเตอร์ประมาณ 3.3 ล้าน ซึ่งเล็กพอจะรันบน CPU

## 6. Baseline

**บนสไลด์**
- X0: Logistic Regression / Random Forest บนสถิติของ landmark
- X1: BiGRU (flatten 54 × 7 → BiGRU) 2.16M params
- อ้างอิงบทความ: SPOTER 80.83%, I3D 79.69% บน split เดิมของ TSL-ONE-S
- จุดตรวจ pipeline: BiGRU ของเราบน split เดิม = **81.2%** → ใกล้บทความ ✅

**พูด**
> ก่อนเชื่อผลใด ๆ เราตรวจ pipeline ก่อน โดยรัน BiGRU บน split เดิมของบทความ ได้ 81.2% ใกล้กับ SPOTER และ I3D ในบทความ แปลว่าข้อมูลที่เราสกัดเองไม่ได้ผิดเพี้ยน

## 7. ผลหลัก: 10 fold signer-independent

**บนสไลด์**

| โมเดล | Top-1 | Top-5 | Macro-F1 |
|---|---|---|---|
| LR / RF (4 fold) | 51.5 / 46.3 | 78.4 / 73.1 | 49.5 / 42.8 |
| BiGRU | 77.6 ± 3.1 | 92.9 ± 1.8 | 76.2 ± 3.6 |
| **S2S-LTR** | **84.8 ± 3.0** | **94.4 ± 1.4** | **83.2 ± 3.8** |

- S2S ดีกว่า BiGRU **ทั้ง 10/10 fold**, +7.2 pp, Wilcoxon p = 0.002, McNemar (4,148 คลิป) p ≈ 2e-34
- กราฟแนะนำ: แท่งต่อ fold สองโมเดลคู่กัน

**พูด**
> บน 10 fold ที่ไม่เห็นผู้แสดง S2S-LTR ได้ 84.8% ดีกว่า BiGRU 7 จุด และชนะทุก fold การทดสอบทางสถิติทั้งแบบจับคู่ราย fold และรายคลิปยืนยันว่าต่างกันจริง
>
> ⚠️ ทุก fold รัน seed เดียว และการเทรนบน GPU ของ Mac (MPS) ไม่ deterministic: BiGRU รันซ้ำ seed เดิมต่างได้ประมาณ ±3 pp ต่อ fold

## 9. X16: ฝึก encoder ร่วมสอง dataset

**บนสไลด์** (แผนภาพ)
```
TSL-ONE-S clip ─┐                         ┌─ head A: 184 คำ (loss เฉพาะคลิป TSL-ONE-S)
                ├─ S2S-LTR encoder ร่วม ──┤
TSL-51 clip ────┘                         └─ head B: 52 คลาส (loss เฉพาะคลิป TSL-51)
```

| Test | joint | เทรนชุดเดียว | Δ |
|---|---|---|---|
| TSL-ONE-S (5 fold) | 83.7 | 84.2 | −0.5 (p = 0.38, ไม่ต่าง) |
| TSL-51 user_sign (คนใหม่) | **80.9 ± 2.9** | 76.2 ± 1.9 | **+4.7** |

**พูด**
> เพราะคำศัพท์สองชุดไม่ซ้ำกัน เราจึงใช้ encoder ร่วมแต่แยก head แต่ละคลิปคิด loss เฉพาะ head ของ dataset ตัวเอง ผลคือ TSL-51 ซึ่งมีข้อมูลน้อยกว่าดีขึ้นเกือบ 5 จุด ขณะที่ TSL-ONE-S ไม่แย่ลง แปลว่า encoder ได้เรียนลักษณะการเคลื่อนไหวของมือที่ใช้ร่วมกันได้ข้ามชุดข้อมูล
>
> ⚠️ p ≈ 0.06 แบบไม่จับคู่ ยังเป็นผลเบื้องต้น

## 10. (งานเพื่อน) RQ-S: spatial / temporal / spatiotemporal

**บนสไลด์**
- คุม input เดียวกัน (C54 xy + mask + hand-local), สูตรเทรนเดียวกัน, fold 4, 3 seed
- ระดับ: **L0** spatial อย่างเดียว · **L1** spatial → temporal · **L2** spatial + temporal พร้อมกัน

| ระดับ | โมเดล | Params | Test top-1 |
|---|---|---|---|
| L0 | B0 MLP + mean pool | 0.18M | 67.6 ± 0.5 |
| L0 | A1 SPOTER (เดิม) | 5.93M | 70.6 ± 3.3 |
| L1 | B1 MLP → BiGRU | 2.14M | 69.0 ± 2.3 |
| L1 | B2 MLP → Transformer | 3.29M | 69.7 ± 1.3 |
| L1 | A2 SPOTER + PE | 5.94M | 69.0 ± 3.3 |
| **L2** | **B3 ST-GCN** | 3.14M | **75.0 ± 1.6** |
| L2 | B4 divided space-time attention | 2.52M | 61.5 ± 3.0 |

- L1 − L0 ≈ +1.4 ถึง +2.2 (ไม่มีนัยสำคัญ) · B3 − B2 = +5.3 (p = 3e-4)

**พูด**
> เพื่อนในทีมตอบคำถามว่าควรเรียนพื้นที่กับเวลาแยกกันหรือพร้อมกัน โดยคุม input และสูตรเทรนให้เท่ากันทุกโมเดล ผลคือการเพิ่ม temporal model ทั้งคลิปแทบไม่ช่วยเมื่อเทียบกับการเฉลี่ยทุกเฟรม แต่ ST-GCN ที่เรียนพื้นที่และเวลาพร้อมกันบนโครงกระดูกดีกว่าชัดเจน 5–6 จุด
>
> ระหว่างทางเพื่อนพบว่า feature สำคัญคือ **hand-local**: พิกัดมือเทียบข้อมือและหารด้วยขนาดมือ ทำให้ val ดีขึ้น 7–12 จุด เพราะในพิกัดเทียบไหล่ มือมีขนาดแค่ประมาณครึ่งความกว้างไหล่ รายละเอียดรูปมือจึงเรียนยาก

## 11. (งานเพื่อน) แยกตัวแปรกวน: ทำไม ST-GCN ชนะ

**บนสไลด์** (ตาราง 2×2)

| | ไม่มี graph prior | มี graph prior |
|---|---|---|
| **L1** แยกพื้นที่ → เวลา | B1 69.0 · B2 69.7 | B6 GCN → BiGRU 69.1 |
| **L2** พร้อมกัน | B4 attention 61.5 (underfit) | **B3 ST-GCN 75.0** |

- graph อย่างเดียวไม่ช่วย (B6 ≈ B1)
- พร้อมกัน + graph ช่วยชัด (B3 − B6 = +5.9, p = 2e-5)
- B3: 9 บล็อก (64 → 128 → 256), temporal kernel 9, กราฟ 57 เส้นบน C54

**พูด**
> เพื่อแยกว่า ST-GCN ชนะเพราะรู้โครงกระดูก หรือเพราะเรียนพร้อมกัน เพื่อนเพิ่มอีกสองโมเดลเป็นตาราง 2×2 ผลคือโครงกระดูกอย่างเดียวไม่ช่วย และ attention ที่เรียนพร้อมกันแต่ไม่มีโครงสร้างกลับแย่ที่สุด ซึ่งน่าจะเป็นเพราะ train ไม่ขึ้น สิ่งที่ทำให้ดีคือการรวมสองอย่าง คือมองข้อต่อข้างเคียงและเฟรมข้างเคียงไปพร้อมกัน ซึ่งเป็น inductive bias ที่ช่วยเมื่อข้อมูลน้อย
>
> ⚠️ **เทียบตัวเลขข้ามทีมตรง ๆ ไม่ได้**: บน fold 4 เดียวกัน S2S-LTR ของเราได้ 80.5% แต่ B2 ของเพื่อนซึ่งสถาปัตยกรรมคล้ายกัน (Transformer 3.29M) ได้ 69.7% เพราะสูตรเทรนต่างกัน (lr, scheduler, epoch, channel) ผลของเพื่อนจึงใช้เปรียบเทียบ **ระหว่างระดับ** ภายใต้สูตรเดียวกัน ไม่ใช่ตัวเลขสูงสุดที่ทำได้ ขั้นต่อไปที่ควรทำคือเทรน ST-GCN ด้วยสูตรของเราดูว่าเกิน 80.5 ไหม
>
> ⚠️ ทั้งหมดเป็น fold 4 fold เดียว

## 14. CSLR: สถาปัตยกรรม C1 (CTC)

**บนสไลด์** (แผนภาพ)
```
ประโยค [T เฟรม × 54 × 7] (30 fps, ไม่ resample)
→ part-aware encoder (เหมือน S2S-LTR, เริ่มจาก weight ของ X16)
→ Conv1d k5 stride 2 × 2  (ลดเวลา 4×)
→ sinusoidal PE → Transformer × 4 (padding mask)
→ Linear → 31 คำ + blank → CTC loss · greedy decoding
```
- 3.88M params
- **ประโยคสังเคราะห์**: ต่อคลิปคำเดี่ยว 3–6 คำ, ตัดหัวท้าย 0–20%, blend 6 เฟรม, สุ่มช่วงพัก → 300 ประโยค/epoch
- 2 protocol: **S-rep** (ประโยคเดิม การแสดงครั้งใหม่) · **S-template** (ลำดับคำที่ไม่เคยเห็น)

**พูด**
> สำหรับประโยค เราไม่รู้ว่าแต่ละคำเริ่มและจบตรงไหน จึงใช้ CTC loss ซึ่งเรียนจากลำดับคำของทั้งประโยคได้โดยไม่ต้องมีขอบเขตคำ encoder ใช้ส่วนเดียวกับโมเดลคำเดี่ยวและเริ่มจาก weight ของ X16 แล้วลดความยาวเวลาลง 4 เท่าก่อนเข้า Transformer
>
> ปัญหาคือมีประโยคจริงแค่ 252 ประโยค เราจึงสร้างประโยคสังเคราะห์โดยต่อคลิปคำเดี่ยวของผู้แสดงคนเดียวกัน โดยไม่ใช้ลำดับคำที่อยู่ใน test

## 15. CSLR: ผล และ CTC vs segment-then-classify

**บนสไลด์** (WER %, ต่ำดี, 3 seed)

| โมเดล | S-rep | S-template |
|---|---|---|
| **C1 CTC (X16 + synth)** | **5.1 ± 0.6** | **11.8 ± 4.8** |
| C1 เริ่มจากศูนย์ | 5.1 ± 0.3 | 13.6 ± 3.0 |
| C1 ไม่มีประโยคสังเคราะห์ | 3.5 ± 1.3 | 36.4 ± 7.6 |
| C2 sliding window + classify (fine-tune) | 30.8 | 27.3 |

- ประโยคสังเคราะห์: ลำดับคำใหม่ WER 36 → 12 (substitution 24 → 2%)
- C2 แพ้ CTC แม้ในประโยคที่มีช่วงพัก (26–30% vs 1–6%) → **H7 ไม่ได้รับการสนับสนุน**
- X16 init ช่วยความแม่นน้อย แต่เทรนเร็วขึ้น ~3×

**พูด**
> CTC ได้ WER ประมาณ 5% บนประโยคที่เคยเห็น และ 12% บนลำดับคำใหม่ สิ่งที่สำคัญที่สุดคือประโยคสังเคราะห์ ถ้าไม่มี โมเดลจะจำลำดับคำของ train แล้วทายตามนั้น WER บนลำดับใหม่พุ่งเป็น 36%
>
> เราเทียบกับอีกวิธีที่ง่ายกว่า คือเลื่อนหน้าต่างไปบนวิดีโอแล้วใช้โมเดลคำเดี่ยวทายทีละช่วง วิธีนี้ผิด 27–31% โดยส่วนใหญ่ผิดตรงช่วงเปลี่ยนท่า ทั้งตัดคำหายและนับช่วงเปลี่ยนท่าเป็นคำ เราคาดว่าวิธีนี้จะใกล้ CTC ในประโยคที่มีช่วงพัก แต่ผลไม่เป็นอย่างนั้น
>
> ⚠️ ผู้แสดงคนเดียว (signer-dependent) · ประโยคแบบมีช่วงพักใน test มีแค่ 8 ประโยค

## 16. Robustness

**บนสไลด์** (กราฟเส้น top-1 vs ระดับ, S2S vs BiGRU, fold 4)
- ความเร็ว 0.5–2× / frame rate 1/4: **ไม่มีผล** (±1 pp)
- แสง 0.4–1.6× / ความละเอียด 0.33× / เบลอ (รัน MediaPipe ใหม่): S2S ตก ≤ 2.4 pp
- หมุน ±15°: S2S −2 pp · ±30°: BiGRU −12 ถึง −15 pp
- **บังมือทั้งสองข้าง 40% ของคลิป: S2S 80.5 → 65.1, BiGRU 73.3 → 44.2**
- **กลับซ้าย-ขวา (คนถนัดซ้าย): 17%**
- ผู้แสดง 29 คน: S2S median 85.1, min 56.9, max 95.7; S2S ดีกว่า BiGRU 28/29 คน

**พูด**
> เราทดสอบความทนทานสองแบบ แบบแรกรบกวน landmark โดยตรง แบบที่สองแก้วิดีโอแล้วรัน MediaPipe ใหม่ เพื่อดูผลรวมทั้ง perception และโมเดล
>
> ระบบทนต่อความเร็ว แสง และความละเอียดได้ดี เพราะ pipeline ปรับเวลาและขนาดให้เป็นมาตรฐานแล้ว จุดอ่อนจริงมีสองข้อ ข้อแรก ถ้ามือหายไปเป็นช่วงยาว ความแม่นตกมาก ข้อสอง ผู้ใช้ถนัดซ้ายใช้ไม่ได้เลย เพราะทุกคนในข้อมูลถนัดขวา ระบบจริงต้องให้ผู้ใช้เลือกมือถนัดแล้วกลับภาพก่อนเข้าโมเดล
>
> S2S ทนกว่า BiGRU ทุกปัจจัย และช่องว่างกว้างขึ้นเมื่อรบกวนหนัก
>
> ⚠️ fold เดียว seed เดียว และเป็นการรบกวนสังเคราะห์

- คำศัพท์ 184 + 51 คำ → proof-of-concept

**พูด**
> ข้อจำกัดหลักคือจำนวน seed และผู้แสดงของประโยค ผลต่างเล็ก ๆ ที่ไม่ถึง 2 จุดยังสรุปไม่ได้ และผล CSLR ยังไม่บอกว่าใช้กับคนอื่นได้ดีแค่ไหน

## 19. สรุปและงานต่อไป

**บนสไลด์**
1. Landmark + Transformer แบบ part-aware: **84.8%** บนคนที่ไม่เคยเห็น, ชนะ BiGRU 10/10 fold
2. รวม dataset ด้วย encoder ร่วม: TSL-51 **+4.7 pp** โดยไม่เสีย TSL-ONE-S
3. การเรียนพื้นที่ + เวลาเฉพาะที่ (ST-GCN) ดีกว่าแยกกัน; hand-local feature สำคัญมาก (งานเพื่อน)
   ⏳ + ผลเมื่อนำมาใช้กับระบบหลัก: "hand-local ช่วย/ไม่ช่วย S2S __ pp; ST-GCN ได้ __% เทียบกับ 84.2%" (จากสไลด์ 13)
4. CTC + ประโยคสังเคราะห์: WER 5% (ประโยคเดิม) / 12% (ลำดับใหม่); segment-then-classify แพ้ชัด
5. Real-time ได้ (42 fps); จุดอ่อน: มือหายนาน, คนถนัดซ้าย

**งานต่อไป**
- ⏳ ขึ้นกับสไลด์ 13: ถ้าตัวไหนชนะ ให้รันตัวนั้นครบ 10 fold × 3 seed และใช้เป็นโมเดลหลักรุ่นต่อไป
- flip augmentation / ให้เลือกมือถนัด
- เก็บประโยคจากผู้แสดงหลายคน
- ทำขั้นแปลเป็นภาษาไทย

**พูด**
> สรุปคือ landmark เพียงพอสำหรับการรู้จำภาษามือไทยระดับคำแบบไม่เห็นผู้แสดง ได้ประมาณ 85% และทำงาน real-time ได้บนเครื่องทั่วไป ข้อค้นพบจากทั้งสองฝั่งของทีมชี้ทางต่อชัดเจน คือการเพิ่ม feature มือแบบ local และโครงสร้างแบบ ST-GCN ซึ่งน่าจะรวมกับโมเดลของเราได้ ขอบคุณครับ/ค่ะ

## ภาคผนวก: คำถามที่น่าจะโดนถาม

| คำถาม | คำตอบสั้น |
|---|---|
| ทำไมไม่ใช้ RGB | ผลแรก 37.5% vs landmark 80.5% บน fold เดียวกัน, landmark มี params น้อยกว่า ~4× (3.3M vs 12.5M) และเร็วกว่า (1.3 vs 13.4 ms); ข้อมูลที่โมเดลเห็นไม่มีฉากหลัง (แต่ยังไม่ได้ทดสอบฉากหลังจริง) |
| ทำไม S2S ของเราได้ 80.5 แต่ B2 ของเพื่อน 69.7 บน fold เดียวกัน | สูตรเทรนต่างกัน: lr 3e-4 + warm-up/cosine + label smoothing + 150 epoch (เรา) vs lr 1e-3 คงที่ 100 epoch (เพื่อน) → ผลของเพื่อนใช้เทียบระหว่างระดับ ไม่ใช่เทียบกับของเรา; การเทียบที่ยุติธรรมอยู่ในสไลด์ 13 (สูตรเดียวกัน) ⏳ |
| ทำไม random split ไม่สูงกว่า SI | random-matched split ใช้ขนาดเท่ากัน และ TSL-ONE-S มีคนละ ~1 คลิปต่อคำต่อคน การเห็นคนเดิมจึงช่วยน้อย (ผลต่าง −1.6 pp อยู่ในระดับ noise) |
| จุดหน้าไม่ช่วยจริงไหม | บน TSL-ONE-S ไม่ช่วย (+0.9 เมื่อตัดออก) แต่คำศัพท์ชุดนี้เน้นท่ามือ; ใน CSLR หรือคำที่ใช้สีหน้าอาจต่างไป |
| WER 5% ดีเกินจริงไหม | ผู้แสดงคนเดียว, 31 คำ, ประโยคเดิม → เป็น upper bound; ลำดับใหม่ 12% สมจริงกว่า |
| ทำไม C2 (sliding window) แย่ | ไม่ได้เรียนช่วงเปลี่ยนท่า → ลบ + แทรกรวม 21–28% |
